# Project instructions for this Expo/React Native course repo

This repository is a collection of independent mobile app exercises, not a single application. Apps live under `2bimestre/`, `3Bimestre/`, and `4bimestre/`, and each folder is usually its own self-contained Expo project with its own `package.json` and scripts.

## Working rules

- Identify the specific app you are changing before editing code. The correct project is usually the nearest folder with its own `package.json` and app entry files.
- Do not assume the root folder is the active app. Most work should happen inside the relevant app directory, such as `2bimestre/react_exemplo/exemplo/` or `4bimestre/aula0911/nome_do_app/`.
- Keep changes scoped to the target app and avoid unrelated projects in the repo.
- Prefer the project's existing structure and naming conventions over introducing new abstractions or framework patterns.

## Expo and React Native guidance

- Check the target app's `package.json` before using any Expo, React Native, navigation, or Firebase API. Expo changes rapidly across SDK versions.
- For any Expo or React Native code change, read the matching docs for the SDK version currently declared in that app, e.g. `https://docs.expo.dev/versions/v<major>.0.0/`.
- If a dependency change is needed, prefer `npx expo install <package>` over `npm install` or `npm add` so the package versions match the app's Expo SDK.
- Do not hand-edit generated native folders like `ios/` or `android/` when they are absent or generated by Expo. Configure behavior via Expo config and app code instead.
- Prefer mobile-first, simple screen-level components and straightforward state handling. This repo is educational and values readability and compatibility over advanced architecture.

## Commands to use

Run commands from the relevant app directory instead of the repository root.

```bash
cd <app-folder>
npx expo start
npx expo start --web
npx expo install <package>
npx expo lint
npx tsc --noEmit
```

Use Expo's project scripts when present (`start`, `web`, `android`, `ios`, `lint`). For projects using Expo Router, follow the router file structure under `src/app/` and keep screen logic in route files unless a shared component or hook is clearly reusable.

## Project-specific patterns

- Older app folders are simple React Native apps using `App.js` with screen/component files and navigation libraries.
- The newer Expo Router example uses `src/app/` and route files with `expo-router`.
- Firebase usage is common in course exercises; keep credentials and config in the app-local Firebase module, not in shared repo-level config.
- Keep visual styling clear and app-specific, especially for course demos and screens.

## Validation

- Validate the change with the smallest relevant command for the target app.
- When TypeScript or linting is available in the app, run the local checks before declaring the task done.
- If no tests exist, at minimum verify the app still starts or the relevant Expo command succeeds for that app.

## Safety and scope

- Do not modify unrelated folders or course exercises outside the target app.
- Do not introduce unnecessary dependencies or rewrite the project into a different architecture unless the task explicitly requires it.
- Favor small, reviewable edits that match the current app's existing patterns.
